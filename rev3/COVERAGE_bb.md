# Case-coverage report (batch bb)

Generated by `generate_bb.py`. Describes prespecified case categories and eligibility only. It contains no model results, and cases are never added or dropped based on model behaviour.

**Separately declared batch run.** Batch bb is one of three batches (ba, bb, bc; 8 cases each) that expand the development set from 12 to 36 cases. The expansion was approved for precision: with 12 independent cases the case-clustered intervals are wide. The batch was authored after the base and extension stimuli were frozen (`stimuli_dev.jsonl` sha256 `368e1d0e…8e67`, `stimuli_ext.jsonl` sha256 `c9d92a01…`), and is run separately with the same frozen model configuration (`configs/p2_dev_eval_v1.json`), renderer, system prompt, task text and condition matrix. Batch cases were not selected or edited based on any model output.

## What batch bb adds

- **Species:** rainbow trout, Nile tilapia, whiteleg shrimp (broodstock), European sea bass, broiler breeders, pullets, Japanese quail, meat geese (base: broilers, laying hens, pigs; extension: dairy cows, Atlantic salmon, turkeys, Pekin ducks, rabbits, dairy calves).
- **Practice types:** water oxygen level, emergency oxygen backup, no eyestalk ablation, crowding duration, mating ratio, dark brooders, soft ceilings, pasture access.
- **Outcome evidence sources:** processing-plant grading (sampled per harvest batch; every carcass), daily mortality logs against delivery and harvest counts, mortality logs against veterinary reports, a contracted fish health assessor (four visits a year), the attending vet's monthly visit reports, an external scorer at a fixed age (16 weeks), daily mortality and cull sheets per bird placed.
- **Measurement windows:** calendar year, harvest year, batch-harvest year, stocking year with a 60-day follow-up, transfer year, depletion year, slaughter year.
- **Issuers:** eight new fictional issuers (none shared with the base or extension set).

## Not covered (known gaps, unchanged by this batch)

- **Template diversity: one family.** Batch cases use the same audit-record layout (`kv-record-v1`) and dossier layout as the base cases, by design (same renderer). Format-specific behaviour still cannot be separated from the effect.
- **Period and population scope.** No condition varies the audited period or audits a subset of the population.
- **Independence.** All cases come from one author (builder). Analysis must cluster on case.
- **Realism.** Thresholds, indicators and methods are unreviewed placeholders (spec §8.6); `EXPERT_VERDICTS.csv` has no rows for batch bb yet (human-owned; add blank rows from `CLAIM_EVIDENCE_RUBRIC_bb.md` row ids).
